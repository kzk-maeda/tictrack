このリポジトリのアプリケーションアーキテクチャをレビューしてください。
目的は、今後の機能追加や開発体制拡大に対して、安全に継続開発できる構造になっているかを評価することです。

単なるコード品質ではなく、以下の設計観点を重視してください。
- 規模と複雑性に対して構造が妥当か
- 変更時の影響範囲が局所化されるか
- フロントエンド / バックエンド / データモデル / インフラの責務分離
- それぞれの境界が適切か
- ドメイン境界やデータモデルがどの程度整理されているか
- 将来壊れやすい構造や、開発者が誤って破りやすい境界がないか
- セキュリティ、認可、整合性、運用性の観点で危険な構造がないか

以下の形式で出力してください。
1. 全体評価
2. 良い点
3. リスク/懸念点
4. 境界レビュー
   - FE ↔ BE
   - BE ↔ Data Model
   - App ↔ Infra
   - Shared/Common ↔ Domain
5. 優先度付き改善提案
   - P0 / P1 / P2
6. 段階的な改善方針

必要に応じてagentteamを立ち上げて調査してください。

なお、
- 今動いているかではなく、今後安全に変更できるかを重視してください
- 一般論ではなく、このリポジトリの構造に即して指摘してください
- 推測しかできない点は明示してください
- 特に「今は成立しているが、規模拡大で崩れるポイント」を重点的に挙げてください
